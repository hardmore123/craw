## 1. 项目一句话

把「安全件报备清单」Excel 表格里的**证书号**逐条到 **VDE / UL / TÜV Rheinland** 三家认证机构官网查询，把官网真实信息与表格内容（制造商、生产厂、型号、标准、证书状态）逐项比对，结论写回 Excel，**不一致字段标红**。已做成本地网页前后端 + 命令行两种用法。

---

## 2. 项目解决了什么问题

安全件报备清单里每一行都填了某个元器件的认证信息，但**填的内容和认证机构官网上的真实信息是否一致，过去只能一条条手工去查**。一张一百多行的表，人工核一遍要小半天，而且容易看漏。

本工具把这件事自动化：

1. 读 xlsx，**多 sheet 都会处理**
2. 逐行取 **I 列（或 J 列）的证书号**
3. 自动路由到对应认证机构官网查询
4. 把官网结果与表格里的**制造商、生产厂、型号、标准、证书状态**五项逐项比对
5. 结论写进 **M 列**，不一致字段**红字标注**
6. 同时产出两份 Excel：
   - **对比表**：原值不动 + 结论 + 不一致红字 + 来源 URL
   - **抓取表**：官网抓取值用**天蓝色字**填入对应列，便于对照

原文件不动，结果另存副本。

## 4. 已实现的功能（完整清单）

### 4.1 三家官网抓取（全部实测打通）

| 机构 | 站点 | 状态 | 抓取方式 | 依赖 |
|---|---|---|---|---|
| **TÜV Rheinland** | www.certipedia.com | ✅ 已验证可用 | 纯 HTTP（urllib），服务端渲染 HTML | 仅 openpyxl |
| **VDE** | www.vde.com（Solr REST JSON） | ✅ 已跑通（需代理） | 直连官方 restSearch JSON 接口，免登录 | openpyxl + 代理 |
| **UL Prospector** | iq.ulprospector.com | ✅ 已打通（E502081 实测） | Playwright + 本机 Edge 登录态，过 Cloudflare | openpyxl + Playwright |

### 4.2 比对功能

- ✅ **五字段逐项比对**：制造商、生产厂、型号、标准、证书状态
- ✅ **三层归一化**：全角半角、大小写、标点、公司后缀（Co.,Ltd. / GmbH 等忽略）
- ✅ **分字段策略**：
  - 制造商/生产厂：归一化后包含判定 + 相似度 ≥ 0.86
  - 型号：集合交集 + VDE 通配符匹配（`*` 编译成正则）+ 相似度 ≥ 0.9 兜底
  - 标准：标准号集合 + 去年份/修订后核心号比对（注明"版本/年份不同"）
  - 证书状态：映射成"有效/失效"两态再比
- ✅ **四态结论**：一致 / 不一致 / 网站无此项 / 表格未填
- ✅ **中英文状态识别**（valid/有效/gültig/withdraw/撤销/...）

### 4.3 路由功能

- ✅ **三级路由**：证书号显式前缀 > 认证类别列 > 证书号形态猜测
- ✅ **证书号归一化**：去机构前缀（`UL E67006` → `E67006`，`VDE 40018250` → `40018250`）
- ✅ **跳过无效证书号**：ENEC 暂不搜索、不含数字的"证书号"（如 "Tested with Equipment"）直接跳过

### 4.4 Excel 输入输出

- ✅ **多 sheet 支持**：两个/多个 sheet 列结构不同可分别配置
- ✅ **表头自动识别**：前端按表头关键词自动识别列映射（证书号/认证类别/制造商/型号/标准）
- ✅ **两份结果表**：
  - 对比表（`_对比结果.xlsx`）：原值不动 + M 列结论 + 不一致红字 + N 列 URL
  - 抓取表（`_抓取结果.xlsx`）：官网值天蓝字填入 + M 列状态 + N 列 URL
- ✅ **原文件不修改**：所有写入都在副本上
- ✅ **样式降级**：着色失败时降级为仅写值，仍保证有结果

### 4.5 网页前后端

- ✅ **上传 → 列映射 → 实时进度 → 结果表 → 双下载** 全链路
- ✅ **上传加密检测 + 自动解密**（magic bytes 判断 + 调解密服务兜底）
- ✅ **进度轮询**：前端每秒轮询进度，显示当前 sheet/证书号/机构/已完成数
- ✅ **取消任务**：支持中途取消
- ✅ **UL 登录按钮**：网页内一键弹出 Edge 登录
- ✅ **列映射自动识别 + 手动下拉选列**
- ✅ **查询间隔可配置**（快速 1s / 稳妥 5s / 保守 15s / 自定义）+ 随机抖动
- ✅ **核对数量分段**（试跑 10 条 / 全部 / 自定义）
- ✅ **字段级明细**：点结果行看每个字段的比对详情（表格值 vs 官网值 vs 结论）

### 4.6 命令行工具

- ✅ `netcheck`：网站可达性自检（抓前必跑）
- ✅ `netdiag`：分层网络诊断（DNS → TCP → TLS → 出口）
- ✅ `query <证书号> --agency <TUV|VDE|UL>`：单条试抓
- ✅ `inspect <xlsx>`：打印表头，确认列映射
- ✅ `run <xlsx>`：全量核对并写回
- ✅ `probe-vde`：VDE 联通后落盘原始 JSON，标定解析规则
- ✅ `parse-file vde <json>`：离线解析手工保存的接口响应

### 4.7 部署与运维

- ✅ **Windows 交付包**：解压即用，含一键启动/网络自检/试跑/全量/UL登录/自测等 bat

- ✅ **防火墙拦截识别**：检测到拦截页默认立刻停止（`stop_on_blocked`）
- ✅ **平台使用数据上报**（可选）：任务注册 + 完成后 usage 上报
- ✅ **端到端自测**：造样例表 → 真实抓取 → 比对 → 写回
- ✅ **5 套离线测试**（全绿）：路由/字段比对/Excel 写入/网页全链路/VDE 解析

### 4.8 CQC 数字开放平台接入

## 7. 核心代码架构详解

### 7.1 分层设计

```
Excel 输入
    │
    ▼
config.py (ColumnMap 列映射) ──→ verifier.py (VerifyEngine 核对内核)
    │                                    │
    │                                    ├── providers/ (ProviderRouter 路由)
    │                                    │       ├── tuv_rheinland.py (HTTP)
    │                                    │       ├── vde.py (HTTP JSON)
    │                                    │       └── ul.py (Playwright)
    │                                    │
    │                                    ├── http_client.py (HTTP 客户端)
    │                                    │
    │                                    └── compare.py (字段比对)
    │                                            │
    │                                            ▼
    │                                    RowOutcome (字段级结论)
    │                                            │
    ▼                                            ▼
excel_writer.py ──→ 对比表 (红字) + 抓取表 (蓝字)
```

**关键设计**：各机构网站字段名各不相同，全部映射到统一的 `CertRecord` 模型，比对层只面向 `CertRecord`，不关心数据来自哪家。所以**新增一家认证机构只需加一个 provider 文件**，比对和 Excel 读写逻辑完全不用改。

### 7.2 数据流（核对内核）

`verifier.py` 的 `VerifyEngine` 是**网页和命令行共用的核对内核**：

```python
eng = VerifyEngine(cfg)
for outcome in eng.iter_rows():     # 惰性逐行产出
    # 上报进度 / 检查取消 / 收集 outcome
# 之后由 excel_writer 落盘
```

- `iter_rows()` 是生成器，逐行产出 `RowOutcome`
- 每行：读 xlsx 取值 → 路由查询官网 → `compare_fields()` 产出字段级 `FieldVerdict` → 组装 `RowOutcome`
- `RowOutcome` 携带每字段所在列字母，供 `excel_writer` 精确标红
- 遇到 `BLOCKED` 且 `stop_on_blocked=True` 时自动停止

### 7.3 字段级结论（单一判断来源）

`compare.py` 的 `compare_fields()` 是 **Web 展示、M 列文案、Excel 标红三者共同的唯一判断来源**：

```python
def compare_fields(sheet_row: dict, rec: CertRecord) -> list[FieldVerdict]:
    # 对五个字段逐一比对，返回字段级结论
    # 只在 rec.status == FOUND 时产出；非 found 返回空列表
```

`FieldVerdict` 包含：field、label、sheet_value、site_value、verdict（MATCH/MISMATCH/MISSING_SITE/MISSING_SHEET）、detail。

## 8. 三家官网抓取路径详解

### 8.1 TÜV Rheinland（Certipedia）— 纯 HTTP，已验证

```
证书详情：GET https://www.certipedia.com/certificates/<数字证书号>?locale=en
搜索兜底：GET https://www.certipedia.com/search/matching_product_certificates?locale=en&q=<证书号>
```

- 服务端渲染 HTML，纯 `urllib` 即可，无需浏览器、无需登录
- 字段映射：Certificate Holder→制造商、Model Designation→型号、Fulfilled Standards→标准、`<h2 class="certificate-status">`→证书状态
- **不公开生产厂**，记"网站无此项"
- 代码：`providers/tuv_rheinland.py`（206 行）

### 8.2 VDE — Solr REST JSON 接口，免登录

```
GET https://www.vde.com/www8/servlet/restSearch/2289904/zertreg-certificates
    ?wt=json
    &fq=(detailDocType:zertreg|certificate)
    &fq=id:zertreg|certificate#<证书号>
    &start=0&rows=50
    &fl=*                    ← 试着取全字段
```

- 必要请求头：`Accept: application/json` + `Referer`（指向搜索页）
- **免登录、免 Cookie**
- 字段映射（对证书号 40052271 真实响应验证）：
  - `companyName_en`/`companyName` → 制造商
  - `typeNames`（数组）→ 型号（含 `*` 通配）
  - `id` → 证书号、`registerNumber` → 注册号、`validityLimit` → 到期日
- **证书状态推断**：接口 fq 强制加了有效期过滤，命中即"有效"
- **标准/生产厂**：默认 fl 无此两项，代码先试 `fl=*`，取不到留空
- 代码：`providers/vde.py`（270 行）

### 8.3 UL Prospector — Playwright + Edge 登录态，过 Cloudflare

```
1. 自动补全：GET /en/suggest/_all?q=<文件号> → 拿 qm=10006:<内部id>
2. 精确查询：GET /en/search/_results?qm=10006:<id> → HTML 结果表
3. 回退：GET /en/search/_results?qm=q:<文件号>
```

- **必须用真浏览器**（Playwright + 本机 Edge channel=msedge）过 Cloudflare

- 代码：`providers/ul.py`（288 行）+ `ul_login.py`（121 行）

## 9. 路由规则详解

`providers/__init__.py` 的 `ProviderRouter.resolve()` 按优先级路由：

| 优先级 | 规则 | 示例 |
|---|---|---|
| 1（最高） | 证书号显式前缀 | `TUV R50151509`→TÜV、`VDE 40018250`→VDE、`UL E67006`→UL |
| - | ENEC 前缀 | `ENEC-02099`→**不搜索**，标"人工核对" |
| 2 | 认证类别列 | 含 UL（含 CB/UL）→UL；纯 CB→VDE；含 VDE→VDE；含 TUV/莱茵→TÜV |
| 3（最低） | 证书号形态 | `E67006`→UL、`40018250`→VDE、`R50151509`→TÜV |

特殊处理：
- **不含数字的"证书号"**（如 "Tested with Equipment"）→ 直接 `unsupported` 跳过
- **证书号归一化**：`UL E67006`→`E67006`、`VDE 40018250`→`40018250`、HA/NA 前缀去字母保留数字

测试见 `tests/test_routing.py`。

## 10. 比对逻辑详解

`compare.py` 分三层处理"同一个意思写法不同"：

### 10.1 归一化

- `norm_text`：NFKC 全角半角、空格归一
- `norm_key`：只留字母数字（强归一化，用于相等判断）
- `norm_company`：去公司后缀噪声词（Co/Ltd/GmbH/Electronics/Group 等一律忽略）

### 10.2 分字段策略

| 字段 | 函数 | 策略 |
|---|---|---|
| 制造商/生产厂 | `cmp_company` | 归一化后包含判定 + 相似度 ≥ 0.86 |
| 型号 | `cmp_model` | 切成集合判交集 → VDE 通配匹配（`*`→正则）→ 相似度 ≥ 0.9 兜底 |
| 标准 | `cmp_standard` | 抽标准号集合 → 精确交集 → 去年份/修订后核心号交集（注明"版本不同"） |
| 证书状态 | `cmp_status` | 映射"有效/失效"两态后比 |

### 10.3 四态结论

| 结论 | 含义 | 是否标 ✗ |
|---|---|---|
| `一致` (MATCH) | 字段对上了 | 否 |
| `不一致` (MISMATCH) | 真的不一致 | **是** |
| `网站无此项` (MISSING_SITE) | 官网没公开这一项 | 否 |
| `表格未填` (MISSING_SHEET) | 表格该列是空的 | 否 |

**只有真"不一致"才标 ✗**。"网站无此项"和"表格未填"不算不一致。

### 10.4 M 列输出示例

```
✓ 一致：制造商、型号、标准、证书状态；（生产厂网站无此项）
✓ 一致：制造商、型号、标准(版本/年份不同: 表格=['en62368-1:2014'] 网站=['en62368-1:2020+a11'])、证书状态
✗ 不一致：型号不一致[表格=A24-999XXX | 网站=A24-065N3A]
✗ 不一致：证书状态不一致[表格=有效 | 网站=Invalid Certificate]
⚠ 官网未查到该证书号（TUV-Rheinland）
✗ 网络被拦截，未能查询（VDE）：vde.com 被公司网络 URL 过滤拦截
```

  ```yaml
  spring.security.oauth2.client.registration.client_local:
    client-id: <CQC 分配>
    client-secret: <开发者设置>
    redirect-uri: <回调 URL>
    authorization-grant-type: authorization_code
    client-authentication-method: client_secret_basic
  env:
    gateway: https://open.cqccms.com.cn/open-gateway
    logout: https://open.cqccms.com.cn/open-auth/logout?callback_type=json
  ```

## 15. 已知限制与易踩坑

### 15.1 硬限制（不是 bug）

| 限制 | 说明 |
|---|---|
| TÜV 不公开生产厂 | Certipedia 无此字段，只能记"网站无此项"，靠证书 PDF 或人工核 |
| VDE 接口无标准/生产厂 | 默认 fl 无此两项，`fl=*` 能否取到需联网实测 |
| UL 列表页无型号/标准 | 在详情页，未实现 `_fetch_detail` |
| 中英文混写比不了 | "东莞" vs "Dongguan, China" 必判不一致，需人工看 |
| 标准差年份不替你决定 | 判一致但注明"版本不同"，是否算问题由人工判断 |
| ENEC 不自动核对 | 标"人工核对" |

### 15.2 易踩坑

| 坑 | 对策 |
|---|---|
| **Python 版本**：PATH 的 python 指向 3.14（没装 openpyxl） | 用 3.12，或用 `_py.bat` |
| **网络**：VDE/UL/TÜV 直连被网关拦 | 开 VPN/加速器，配代理 |
| **UL 需登录态**：`.ul_profile/` 不打包不提交 | 每台电脑/服务器各登一次 |
| **UL 与网页抢 profile**：Playwright 持久化目录独占 | 跑 CLI 抓取前先停网页服务 |
| **Excel 被打开时无法覆盖**：出现 `~$xxx.xlsx` 锁文件 | 生成前先关 Excel |
| **PowerShell `Set-Content` 改 .py 破坏 UTF-8**：中文变 GBK | 用编辑器/edit，别用 Set-Content |
| **查询间隔 15s**：全量很慢（250 行 ≈ 1 小时） | 小样用 limit 参数 |
| **systemd 不加载 .env**：`os.getenv()` 读不到 | 用 EnvironmentFile= 或让程序自己 load dotenv |
| **断电后服务 failed**：systemd 默认 StartLimitBurst=5 | 已设 `StartLimitIntervalSec=0`，别改回默认 |
| **iGG 浏览器扩展代理**：只代理浏览器内流量，脚本走不了 | 需开挂系统代理的 VPN/加速器 |

### 15.3 敏感数据清单
