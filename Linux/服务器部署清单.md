# 证书核对工具 · 服务器部署清单（可直接照做）

> 目标：把 `cert_verify.web` 部署为 systemd 托管的常驻服务，Nginx 做纯反向代理。
> 服务器：`10.18.87.51`（Linux, 用户 `hisense`, Python 3.11）
> 项目目录：`/home/hisense/pro/Gitlab/DataGather`
> 端口：后端 `127.0.0.1:8756`，Nginx 对外 `80`
>
> 每一步都给了**验证命令**和**期望输出**。看到期望输出再进行下一步。
> 借鉴 CertAgent 部署经验，重点规避 **Nginx 权限/ACL** 与 **路径/端口** 两类坑。

---

## 0. 两条最重要的经验（先读）

1. **Nginx 只反代、不读文件**。本工具的静态页由 Python 后端自己托管，Nginx 只
   `proxy_pass` 到 `127.0.0.1:8756`。这样就**完全避开** CertAgent 那种
   `www-data` 读 `/home/hisense/.../dist` 的 ACL / 500 权限坑（那套 `setfacl`
   这里根本用不上）。

2. **端口会静默 +1**。`serve()` 发现 8756 被占用会自动尝试 8757…8775。
   所以切 systemd 前**必须先停掉旧 nohup 进程**，否则新服务会悄悄绑到别的端口，
   Nginx 反代 8756 就会 502。

## 7. 安装 systemd 服务

服务文件已在仓库：`Linux/deploy/certverify.service`（已含 `HOME`、`LANG`、
解密服务环境变量、`--host 0.0.0.0 --port 8756 --no-browser`）。

> 若走 Nginx 反代且不想对外暴露 8756，把 service 里的 `--host 0.0.0.0`
> 改成 `--host 127.0.0.1` 再安装（见第 8 步说明）。

```bash
cd /home/hisense/pro/Gitlab/DataGather
sudo cp Linux/deploy/certverify.service /etc/systemd/system/certverify.service
sudo systemctl daemon-reload
sudo systemctl enable --now certverify
```

**验证**：

```bash
sudo systemctl status certverify --no-pager        # 期望：active (running)
ss -ltnp | grep 8756                                # 期望：能看到 python 监听 8756
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8756/   # 期望：200
sudo journalctl -u certverify -n 30 --no-pager      # 期望：打印“证书核对网页已启动”
```

> 若 `curl` 不是 200 或端口不是 8756：多半是第 6 步旧进程没杀干净导致端口 +1。
> 回到第 6 步确认 8756 已释放，再 `sudo systemctl restart certverify`。

**验证环境变量确实加载**（借鉴 CertAgent：systemd 不自动读 .env）：

```bash
systemctl show certverify -p Environment
# 期望包含：HOME=/home/hisense LANG=C.UTF-8 DECRYPT_URL=http://10.18.87.51:8500/parse_file ...
```

## 8. 安装 Nginx 反向代理（纯 proxy_pass）

若只在服务器本机/内网用 8756 访问，可跳过本步。要统一走 80 端口再做这步。

**建议**：先把后端改为只监听本机，避免 8756 直接对外：

```bash
sudo sed -i 's/--host 0.0.0.0/--host 127.0.0.1/' /etc/systemd/system/certverify.service
sudo systemctl daemon-reload && sudo systemctl restart certverify
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8756/   # 期望：200
```

安装 Nginx 与配置：

```bash
sudo apt update && sudo apt install -y nginx
cd /home/hisense/pro/Gitlab/DataGather
sudo cp Linux/deploy/nginx-certverify.conf /etc/nginx/sites-available/certverify
sudo ln -sf /etc/nginx/sites-available/certverify /etc/nginx/sites-enabled/certverify
sudo rm -f /etc/nginx/sites-enabled/default      # 去掉默认站点（可选）
sudo nginx -t                                     # 期望：syntax is ok / test is successful
sudo systemctl reload nginx
```

**验证**：

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1/        # 期望：200（经 Nginx）
curl -sI http://127.0.0.1/ | head -n1                             # 期望：HTTP/1.1 200 OK
```

> 这里若 502：后端没起或端口不对（回第 7 步）。
> 若 404/欢迎页：默认站点没去掉或软链没生效，检查 `sites-enabled`。
> **不会**出现 CertAgent 的 ACL 500，因为 Nginx 不读文件。

## 13. 排查速查表（对照 CertAgent 教训）

| 现象 | 最可能原因 | 处理 |
|---|---|---|
| `curl 127.0.0.1:8756` 不通 / 端口不是 8756 | 旧 nohup 没杀，端口被占后 +1 | 第 6 步杀旧进程，重启服务 |
| 经 Nginx 502 | 后端没起或绑的不是 8756 | 查 `systemctl status certverify`、`ss -ltnp\|grep 8756` |
| Nginx 显示欢迎页/404 | 默认站点没去掉或软链没建 | 检查 `/etc/nginx/sites-enabled/` |
| 解密没生效 | 环境变量没加载 | `systemctl show certverify -p Environment` 看 DECRYPT_* |
| 中文文件名乱码 | systemd LANG 为空 | service 已加 `LANG=C.UTF-8`，重启生效 |
| UL 一直转/被拦 | 登录态失效或 Cloudflare | 重新 `xvfb-run ... ul_login`，调大间隔 |
| 多实例数据错乱 | 起了多个网页进程 | 保持单实例（内存态任务表），只用 systemd 一个 |

> 与 CertAgent 的关键差异：本工具**不需要 LibreOffice、不需要给 Nginx setfacl**。
> Nginx 只反代，路径权限只要 `hisense` 自己能读写项目目录即可。
