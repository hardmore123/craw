# 止损指南：判定该手写适配器

> 这不是失败，是**正确的边界判断**。硬凑出一份跑不全的 schema 比诚实报告更糟——
> 它会污染交付数据。
> 已验证案例：Hisense US（期望 181，通用引擎只能拿到 29~64）

---

## 五个止损信号

命中任一，立即停止调参：

| 信号 | 为什么通用引擎做不了 | 实例 |
|---|---|---|
| **型号 slug 无规律** | 通用正则无法可靠框住 | Hisense US：`75u7sg` / `tv43qd40r` / `40qd40r` 混用 |
| **Load More 点不开** | 通用点击候选选择器覆盖不到 | Hisense US Wix 站 |
| **需多级页面才拿到型号** | 引擎只探单层（P0-1 缺口） | 松下、夏普 |
| **数据来自带签名的接口** | `xhr_api` 未实现，且动态签名难复现（P0-2 缺口） | TCL、Samsung、LG |
| **规格需点 tab 展开** | 无对应解析档位 | TCL 类 SPA |

补充的硬止损：强反爬（Cloudflare / 验证码 / 指纹检测）——LLM 改选择器解决不了。

---

## 止损后必须做的三件事

### 1. 记入 cases.jsonl（`verdict: "needs_handwritten"`）

必须写清 `gap` 字段——**缺哪个引擎档位**，这是 P0 排期的直接输入：

```json
{"code":"xxx_us","verdict":"needs_handwritten",
 "signals":{"...探测到的真实信号..."},
 "result":{"expected_models":181,"discovered":"29~64"},
 "gap":"通用 Load More 点击能力 + 无规律 slug 的型号提取",
 "lesson":"一句话说清为什么通用引擎做不了"}
```

### 2. 保留探测现场

`data/probe/<code>_entry.html` 别删。后续实现该能力档位时，
这份 HTML 就是现成的离线测试样本，不用再联网。

### 3. 区分"引擎缺口"与"这站就是怪"

| 类型 | 处理 |
|---|---|
| **引擎缺口**（多级、xhr_api、tab 展开） | 值得投入实现，能一次覆盖一批站 |
| **单站特异**（slug 完全无规律、强反爬） | 直接手写适配器，不要为它扩引擎 |

判断标准：**这个能力能覆盖几个站？** 只能覆盖 1 个 → 手写。能覆盖一类 → 扩引擎。

## 手写适配器的成本参考

现有手写适配器规模，供评估投入：

| 站点 | 行数 |
|---|---|
| samsung_mx | 502 |
| samsung_us | 376 |
| tcl_us | 374 |
| lg_ca | 277 |
| philips_ca | 224 |

难站确实要 300~500 行。这也说明：**如果一个引擎档位能替掉两三个这种适配器，
就值得实现。**

---

## 不要做的事

- ❌ 放宽 `expected.model_count` 或删掉它，让找全率闸门失效
- ❌ 把 `link_selector` 改成超宽泛选择器凑数量（会混入非电视）
- ❌ 造引擎不认的字段假装配上了
- ❌ 把 `verdict` 写成 `success` 但 coverage 只有 50%

这些都会导致"抓了一半当成功"——技术方案 §9.3 明确指出，
**误判成功比抓不到更危险**，因为它污染交付数据且难被发现。
